## 入口 loading 屏卡死 73%（IIS 实机，晚间）

- 现象：进度停在 73%，控制台无报错，只反复打印 `[entryLoader] waiting for manifest resources to complete...`。
- 定位手段（有效，可复用）：控制台跑脚本遍历 `performance.getEntriesByType('resource')` 与 `window.__entryLoaderManifest` 做匹配表，直接看出哪几项 `matched:false` + 打印 `__loaderResourceLoaded/__loaderResourceTotal`。本次输出 7/9，缺 `assets/GisData-DlxCAkNv.js` 与 `assets/GisData-C3PbBUgJ.css`。
- 根因：`vite.config.ts` 的 `entryLoaderManifest` 插件把入口 chunk 的 **dynamicImports**（路由级 lazy import，如 `() => import('~/components/data/GisData.vue')`，4.5MB）和**所有顶层 .css** 都算成"初始必需资源"。但路由级 chunk 只在 vue-router 解析路由时才发请求，且 vite 不为它生成 `<link rel="modulepreload">`（本次 dist 只有 4 个 vendor 的 modulepreload），PerformanceObserver 永远等不到 → `canHideLoader()` 恒 false。
- 修复（vite.config.ts）：BFS 只递归 `chunk.imports` 不再收 `dynamicImports`；CSS 改为只收 initialChunks 自身的 `chunk.cssFiles`（不再全收顶层 .css）。清单 9 项 → 5 项（index + 4 vendor）。
- 注意：vite `generateBundle` 阶段 `chunk.cssFiles` 可用（顶层入口 css 与 monaco css 因本次无 chunk 静态引用故未入清单，属预期）。
- 验证：重新 `pnpm exec vite build` 后 dist/index.html 清单 5 项、`GisData` 已排除；打包 `release/gis-tools-fix-loader.zip`（38 条目 4.93MB，含 web.config）。
- 排障提示：换版本后 loading 卡死优先查「旧 sw.js 残留」（DevTools → Application → Service Workers → Unregister + Clear site data），旧 SW 会拦 chunk 请求。

## 100% 后白屏（真因：遮罩未移除，非路由问题）

- 现象：进度到 100% 后页面全白，控制台无报错。**注意：我一度误判为路由 base 问题，实际不是**（实测 `/gis-tools` 与 `/gis-tools/` 都能渲染出 `gis-data-page`）。
- 根因：`#entry-loader-mask` 遮罩未移除，盖在已渲染好的页面上（`gisDataRendered:true` 但 `maskInDom:true, opacity:1`）。移除只由 Worker 回传 `done` 触发；而 `public/entry-loader-worker.js` 动画循环用了 `requestAnimationFrame`——**DedicatedWorkerGlobalScope 没有这个 API**，循环首帧即抛 ReferenceError 停摆，`cycleRemaining` 冻结（实测 3299.9 不再变），`entryLoader.ts` 的 `cycleRemaining <= 50` 永不成立 → 永不 `__startEnding()` → 遮罩留存。Worker 内部错误不打主页面控制台，所以"无任何报错"。
- 修复三处：
  1. `public/entry-loader-worker.js` 顶部加 rAF/cAF 的 setTimeout polyfill（仅当不存在时）。
  2. `index.html` 的 `__startEnding` 加 2s 后强制 `cleanupLoader()` 兜底。
  3. `src/composables/entryLoader.ts` 加 `CYCLE_MAX_WAIT_MS=5000`，hideStarted 超时强制进 finishing。
  4. 顺带加路由兜底 `{path:'/:pathMatch(.*)*',redirect:'/'}`（base 与无尾斜杠不匹配时 router-view 会空白）+ `App.vue` 用 `<Suspense>` 包 router-view 显示 fallback（GisData 4.5MB 不再阻塞首屏后的空白空档）。
- **验证方法（重要，可复用）**：headless Chrome 的 `--virtual-time-budget` 下 rAF 不推进，会造成"一切冻结"的假象，**不能用来判断动画类问题**。正确做法：起 Node 静态服务器（模拟 /gis-tools 子应用）+ Chrome `--remote-debugging-port` + Node 22 全局 `WebSocket` 连 CDP，`Page.navigate` 后真实 sleep 再 `Runtime.evaluate` 读状态。另需加 `--disable-background-timer-throttling --disable-renderer-backgrounding` 防 rAF 节流。
- 实测结果：正常路径 4s 时 txt=100%/mask 在，8s 时 maskInDom=false（已移除）；把 workerUrl 改坏模拟 Worker 失效，8s 时 mask 同样被移除 —— 两条路径都不会白屏。
- 产物：`release/gis-tools-fix-blank.zip`（38 条目 4.93MB）。

## 修复：历史数据移除按钮不显示（20:24-20:40）

- 现象：历史数据卡片没有移除按钮（DOM 里是 `<!---->` 占位）。
- 根因：Vue 布尔 prop 陷阱——`defineProps<{ removable?: boolean }>()` 未传该 prop 时运行时取 `false`（非 undefined），导致 `v-if="removable !== false"` 恒假，按钮永不渲染。两个使用点（GisData 空状态列表、GisDataReader 历史弹窗 tab）都没传 removable，所以两处都缺。
- 修复：HistoryDataList 改用 `withDefaults(defineProps, { removable: true })`，调用点无需改动。
- 验证（种入 IndexedDB 测试记录后 playwright 实测）：按钮渲染 ✅（桌面端 hover 显现，opacity 0→1）；点击出确认框「确认移除历史数据「xxx」？移除后不可恢复。」✅；确认后 DB 行数归 0、列表联动刷新回空状态 ✅；ESC 取消不删 ✅。
- 经验：可选 Boolean prop 想"默认 true"必须 withDefaults，`?: boolean` 不行。dist 已重新构建（含 4490 config）。
